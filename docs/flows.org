** Library Screen

On first load, a full-screen library overlay shows the available books as cover cards (first page image + title). Tapping a card loads that book and proceeds to the review screen (if the book has priority or new-word characters) or directly to reading. The "Library" toolbar button re-opens the library at any time to switch books. The 繁/簡 toggle works in the library (updates the title and book names). All reading keyboard shortcuts are disabled while the library is open; only T (variant toggle) works.

** Review Screen

The review screen splits characters into two labeled groups: 複習 (review) for priority characters the child already knows, and 新字 (new words) for the book's new-word characters. Each group is a labeled section with its own grid of flashcards. The child taps each card to review before reading.

** Book Screen

A reminder strip shows the current page's 複習 (priority) and 新字 (new word) characters in regular reading font. Only characters present on the current page are listed. Each group shows only when it has characters on the page. The strip updates when navigating pages or toggling 繁/簡. On landscape (wide) screens the strip is a narrow vertical sidebar to the right of the page image. On portrait (tall) screens it becomes a horizontal strip below the page image.

The parent reads the page. Phrase by phrase while hitting "down" button. When the child recognize a word they can press space, or taps cards. Each tapped card fades its background to reveal the illustration.

Tapping a priority card counts down the priority counter in the toolbar.

Tapping a new-word card pops a random unicorn from the Prize collection, colored in a random bright theme. The card then fades like any other.

The child finds all priority cards on the page. The rest auto-reveal. All cards fade out to show the full picture.

The child returns to a completed page. The illustration shows directly. No cards appear. Reset brings the cards back.

"Reveal All" skips the priority requirement. It reveals every card on any page.

** Reading Spotlight

While reading, the parent uses the keyboard to guide the child phrase by phrase. Pressing ↓ (Arrow Down) moves a gentle highlight to the next phrase in reading order (right-to-left, top-to-bottom); ↑ (Arrow Up) moves to the previous phrase. The first ↓ from a fresh page lights the first phrase; at either end the highlight clamps in place (no wrap). The highlight is a small accent-colored dot in the top-right corner of every card in the current phrase — present enough to spot, gentle enough not to distract. It shows on both face-up and revealed cards. The highlight clears on page change, 繁/簡 toggle, Reset, and when the page completes and all cards fade out. ←/→ still flip pages; ↑/↓ are reserved for phrase-by-phrase guidance. It is disabled while the review screen or edit modal is open.

Pressing Space reveals all cards in the currently spotlit phrase (fades their backgrounds to show the illustration, same as tapping each) and auto-advances the spotlight to the next phrase so the parent can continue reading without switching keys. If all cards in the phrase are already revealed, Space just advances. If no spotlight is active, Space does nothing — press ↓ first to start guiding. Space is disabled while the review screen or edit modal is open.

Phrases are auto-segmented by a Python script (~segment_phrases.py~) using jieba word segmentation and stored per-page in ~book.json~ as a =phrases= array. Parents can fix segmentation mistakes in the Edit modal using =|= as a phrase separator (e.g. =安稳|与|独角兽=). When a page has no phrases, each character is its own phrase (character-by-character fallback).

** Integration test (UI)

Start the local server:

#+begin_src bash
python3 -m http.server 8000 --directory app &
#+end_src

Check the DOM with headless Chromium:

#+begin_src bash
chromium --headless --no-sandbox --disable-gpu --dump-dom http://localhost:8000/ | grep -oE 'card-wrapper|review-card|book-page|unicorn'
#+end_src

Verify no JS console errors. A silent page with no cards means a script crash. Check that all expected elements render. Check that new feature elements appear and verify it works as described in user flow. 

Kill the server after testing:

#+begin_src bash
fuser -k 8000/tcp
#+end_src

** Code review

Load the ~code-review-analysis~ skill. Audit the changes for code quality, security, performance, and best practices.

Check for duplicated patterns. Check for XSS: use ~textContent~ not ~innerHTML~ for user data. Check for unnecessary DOM lookups. Check for silent catch blocks. Check that ~will-change~ only targets compositor-friendly properties.

Fix any issues before committing. Look for regressions from earlier steps. A common one: referencing ~dom.*~ before ~initDomCache()~ runs.

** Commit

Write a clear commit message. Describe what changed and why.

Work on a branch if the user requests it. Squash-merge to ~main~ after all steps pass.

** Feedback

Tell the user what you did. Tell them what you verified. Mention any issues or trade-offs. Keep it short.

Use =python scripts/extract_pdf.py --name 安稳与独角兽 "/home/yizhe/Src/charbook/安稳与独角兽.pdf"= to extract all pages of a new book it a folder.

New book might have preface, intro, end note. Children are not going to care about them. Remove those pages.

Then run =python scripts/gen_book.py 安稳与独角兽= to create a template to dictate the book content.

Dictate the book content to the generate json. The book is stored in a single script (declared by the =script= field in book.json, e.g. ="trad"= or ="simp"=). The app converts to the other script at runtime via opencc-js; no dual-field duplication is needed. 

Then run =python scripts/segment_phrases.py 安稳与独角兽= to auto-segment each page's chars into phrases for the reading spotlight. Fix any segmentation mistakes in the Edit modal using =|= as a phrase separator.

Then run =python scripts/recommend_words.py 嘿我是独角章 --all=

** Agent-driven pipeline

Use =python scripts/agent_book.py 嘿我是独角章 "嘿我是独角章.pdf"= to run the full pipeline as an LLM agent loop via Lisette. The agent (an LLM with tool-calling) drives every decision:

1. *Extract* PDF pages to JPGs.
2. *Classify* the first/last few pages using a vision model to identify non-story content (copyright, ISBN, author intro, blank, end notes). Remove them, keeping the title page + story pages.
3. *Tiered OCR* per page:
   - Tier 1: PDF text extraction (instant, perfect if the PDF has a text layer).
   - Tier 2: Tesseract OCR (local, fast, moderate accuracy).
   - Tier 3: Vision model OCR (API call, highest accuracy).
   Escalates automatically when a tier returns fewer than 5 CJK characters. A probe on the first page detects if tesseract is worth trying — if not, skips straight to the vision model for all pages.
4. *Review* OCR results, re-OCR poor pages with the vision model.
5. *Segment* phrases, *recommend* priority words, and *set* metadata (script, priority, new_words).

Requires =FIREWORKS_API_KEY= (or other provider key) and Chinese tesseract traineddata in =scripts/tessdata/=. Use =--agent-model= and =--vision-model= to override the LLM models.
